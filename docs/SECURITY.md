# 2Password 安全设计与边界

[English](SECURITY.en.md) · 简体中文

本文面向使用者和审阅者。这里区分设计目标、实现措施和未承诺的保证；自动化测试通过不等于独立密码学审计。

## 保护目标

攻击者拿到加密包、知道程序源码、可以修改包中的任意字节，并可以无限次离线尝试密码。在用户选用足够强的密码、运行可信程序且系统未被控制的前提下，攻击者应无法读取文件内容或文件名；内容损坏、密码槽篡改、记录重排、截断和未经允许的尾随数据必须导致失败，不能被报告为成功还原。

拥有任意一个有效密码的人都被授权读取**全部**内容。多个密码不是分片、门限解密或需要同时输入的多因素认证。

## 使用的成熟实现

- `Konscious.Security.Cryptography.Argon2` 提供 Argon2id 密码派生；应用不自行实现 Argon2。
- .NET `System.Security.Cryptography.AesGcm` 提供 AES-256-GCM；随机数来自 `RandomNumberGenerator`。
- .NET `System.Formats.Tar` 的 PAX writer/reader 提供标准归档；文件名按 UTF-8 无损处理。
- 默认 Zstandard 压缩由 `ZstdSharp.Port` 提供；可选 Brotli 由 .NET `BrotliEncoder` / `BrotliDecoder` 提供。每个数据块独立压缩，也可以完全不压缩。
- 可选恢复记录由内置、校验固定 SHA-256 的 `par2cmdline-turbo 1.5.0` 提供。随程序提供对应源码和 GPL 许可文本。

项目自有部分是多密码信封格式、流式认证记录、文件系统约束和界面。这些组合逻辑仍需审阅；采用成熟基础库不能自动证明组合协议安全。

## 多密码为何相互独立

每个包生成一个随机 256 位内容密钥。每个密码拥有独立随机盐，使用 Argon2id 派生独立的密钥包装密钥，再以 AES-256-GCM 包装同一个内容密钥。包只保存盐、nonce、密文和认证标签，不保存明文密码，也没有可以“列出其他密码”的密码表。

当前容器格式版本 2 的参数固定为：

| 参数 | 值 |
|---|---|
| Argon2 变体 | Argon2id，版本 1.3 |
| 内存 | 64 MiB |
| 迭代次数 | 3 |
| 并行通道 | 4 |
| 每个密码的随机盐 | 16 字节 |
| 派生密钥、内容密钥 | 32 字节 |
| AES-GCM nonce | 12 字节 |
| AES-GCM 认证标签 | 16 字节 |
| 密码数量 | 1–16 个 |

这一 Argon2id 参数组来自 RFC 9106 给出的低内存选项。参数按格式版本固定，包内无法指定任意大的 KDF 内存或迭代次数来耗尽资源。

知道一个密码会得到内容密钥，但不能从该密钥直接反推出其他密码。攻击者仍可以针对其他密码进行离线字典猜测。**整个包的实际保密性取决于最弱的有效密码**；增加一个很弱的密码会降低整个包的防护能力。删除旧包之外，不能撤回已经发出去的旧副本中的访问权限。

密码按原始 Unicode 字符序列编码，不去除首尾空格、不自动改变大小写、不进行 NFC/NFD 归一化。无效 Unicode、空密码、重复密码及超长输入会被拒绝。

## 内容认证与解析

归档流分为至多 1 MiB 的原始块。每一块独立压缩后单独通过 AES-GCM 认证；压缩不划算的块保留原始编码。解码任意一块不需要前一块的压缩字典。Nonce 由随机前缀和递增的 64 位记录编号组成；每个包有新内容密钥。每条记录的附加认证数据包含完整逻辑包头的 SHA-256、记录编号、原始长度、编码长度、算法标识和保留字段。因此改动未使用的密码槽，也会在数据解密时被检测。

原始块和编码块长度都经过上限检查。解压使用调用方分配的固定大小缓冲，不按攻击者在压缩头中声称的尺寸分配内存。Zstd 必须是单个标准帧、无外部字典、窗口不超过 1 MiB、内容大小恰好等于认证声明；Brotli 必须恰好消耗一块数据并生成声明的字节数。额外压缩帧、尾随字节和长度不匹配会被拒绝。

密钥槽和容器参数的逻辑包头保存为三个固定大小副本；定位尾部也保存为三个副本，各自带 SHA-256 检查值。损坏副本可以被忽略，完整副本之间必须一致。检查值用于发现损坏，不能代替 AES-GCM 认证。副本全部丢失时仍需要 PAR2 或原始备份。文件级目录信息位于 PAX 认证数据内，由内容认证和可选 PAR2 一起保护。

一个专门的、已认证的零长度终止记录是格式的一部分。解密必须检查终止记录、精确的数据边界和实际文件尾，才能完成提交。成功解开一个密码槽不意味着包的完整性已经验证。

解密首先验证记录，再将认证后的明文交给归档解析器。解析器不信任文件名、声明长度、文件数量或归档类型：长度和数量有边界，声明总量与实际读出的总量必须一致，未知格式版本被拒绝。

可见包头会泄露格式版本、密码槽数量、压缩选项、文件/目录数量及声明的总字节数；物理文件长度也可见。文件名、目录名和文件内容位于加密区域。`Inspect` 仅检查格式，不等同于密码验证或完整性验证。

输出 EXE、`.2pw` 及 PAR2 文件本身的名称也可见。界面默认根据源名称建议输出名称，因此包内名称加密不会隐藏你选择的外部包文件名；敏感时请改用不透露内容的输出名称。

## 路径、编码和文件一致性

Windows 文件系统把名字视为 Unicode 字符序列。程序不把文件名转换到本地代码页，不对名称进行 Unicode 归一化；例如 `café.txt` 和由 `e` 加组合重音组成的名称可以分别保留。

文件系统访问使用 Unicode 和扩展长度路径；应用清单启用长路径。Windows/文件系统本身仍有总路径和单个路径分量长度限制，目标磁盘的可用空间也必须足够。Explorer 对很长路径的支持与底层文件 API 不完全相同。

解包只允许安全的相对路径，拒绝绝对路径、盘符、UNC 路径、`..`、备用数据流语法、保留设备名、名称冲突，以及不适合普通 Windows 文件夹的末尾点/空格等名称。不会自动重命名、截断名称或替换乱码后继续。

源目录包含隐藏项和系统项；扫描失败不会静默跳过。为避免数据或含义丢失，下列输入明确拒绝：

- 符号链接、目录联接及其他重解析点，包括可能需要云端取回的占位项；
- 除下载标记 `Zone.Identifier` 以外的 NTFS 备用数据流；该标记在 64 KiB 上限内按原始字节保存，超限明确拒绝；
- EFS 加密、设备和离线文件属性；
- 无法读取、正在被独占使用、或打包过程中检测到变化的源项；
- 不能在普通 Windows 目标目录无歧义表示的名称。

普通文件的字节内容、文件/目录名称、空目录、支持的时间戳及常用属性被还原。它不是完整磁盘镜像：不承诺保留 NTFS ACL/所有者、硬链接关系、稀疏分配布局、短文件名、文件 ID、审计信息或全部文件系统私有元数据。硬链接的字节可以被还原为独立文件；稀疏内容可能占用更多磁盘空间。

扫描和前后复核用于发现普通并发变化，但不是 VSS 快照服务，也不能对正在变化的数据库或整个目录树提供跨文件事务快照。应在源数据稳定时打包；对活跃数据库，应先用对应软件导出一致的备份。

## 原子发布、取消与故障

创建时归档/压缩数据直接流入加密层，不先生成明文临时归档。最终包先写到同目录的临时文件，成功后以不覆盖方式发布。

解包写到一个新建的暂存目录，目录 ACL 限制为当前用户和 SYSTEM；完成全部认证、路径检查、长度检查之后，再以不覆盖方式重命名到新目标目录。目标已经存在或同时被其他进程创建时，操作失败，已有内容保持原样。

正常异常或取消会触发清理。断电、强制终止、磁盘损坏或清理权限丢失，可能留下临时文件/暂存目录。删除临时明文不是安全擦除，尤其不能保证 SSD、备份、文件系统日志或快照中不存在残留。

## 自解密 EXE 的信任边界

独立 EXE 内含程序运行所需组件，不要求收件人另装 .NET 或 2Password。自动布局按最终加密大小选择：能在 Windows 可执行文件限制内保存时，将内容内嵌到 EXE；超过限制时输出一个解密 EXE 和配套 `.2pw` 文件。分离模式下必须把两个文件一起保存、复制；可在界面中主动选择分离模式。

单个 EXE 必须小于 4 GiB。压缩后能满足限制的较大原始数据仍可使用内嵌模式；分离数据使用 64 位长度，原始内容上限为 16 TiB，且受可用空间、条目数、路径及元数据资源限制约束。分离引用只允许一个同目录的安全 `.2pw` 文件名，并绑定其逻辑包头 SHA-256；不支持路径、URL 或跨目录寻址。引用描述和定位尾部也有三个副本。

数据认证保护内容载荷，不会自动为 Windows 可执行代码建立发布者身份。

被人恶意替换的 EXE 可以在密码输入时窃取密码。请只运行来源可信的 EXE，并通过可信渠道核对发布版本或校验值。第三方提供的数据包也可由自己信任的已安装 2Password 程序打开，以减少直接运行陌生 EXE 的必要性。

程序不防御已控制当前用户会话的恶意软件、键盘记录器、管理员或内核级攻击、内存转储、屏幕捕获、弱密码、用户主动共享已解密内容。托管运行时中的字符串和 KDF 内部工作内存不能获得绝对的擦除保证；代码会尽量清零自己控制的密钥和字节缓冲。

## PAR2 恢复、预检与顺序

PAR2 对已经加密的 EXE/数据文件生成恢复信息，不接触文件内容的明文，也不需要知道任何密码。恢复索引和恢复分卷内重复保存定位、文件描述与切片校验元数据；索引缺失或损坏时，可以从完整分卷重新取得这些信息。

正常解包默认只做一次受认证的流式读取，不额外预扫整个文件。密码未匹配任何槽时直接失败，不自动启动 PAR2。若容器、数据或归档验证发现损坏，且存在配套恢复记录，应用会先在副本上检查并尝试修复加密输入；修复成功后重新开始完整的 AES-GCM 认证和解包。首次尝试的临时明文会被清理，只有完整成功后才提交目标目录。每块数据始终在认证通过后才进入解压器。

需要提前检查的用户可以显式选择解包前校验，或使用独立的检查/修复入口。独立块压缩有助于限制损坏的影响范围；它本身不修复缺失的数据，实际恢复来自额外的 PAR2 恢复块。

恢复按受损切片计算。选择 10% 冗余不代表任意分布的 10% 字节损坏都可恢复；散布在很多切片中的少量错误也可能耗尽恢复能力。恢复分卷自身损坏、丢失同样会降低能力。安全预检整体排除未完整通过校验的分卷，不把部分验证过的文件交给原生工具。

恢复前校验所有包的边界和 MD5、恢复集 ID、文件 ID、文件名和受保护文件集合；仅接受所选 EXE 与对应数据文件，或单个数据文件。拒绝目录穿越、备用流、保留名、大小写冲突、冲突描述及 Unicode 文件名覆盖扩展。复制到权限受限的工作区后再次预检，只有通过验证的副本才能被原生工具发现。修复只在副本上进行，全部结果通过独立长度和摘要核验后才提交；受损原文件保留备份。

PAR2 的 MD5 是格式规定的损坏校验，并不是发布者身份或对恶意篡改的密码学认证。重建后的载荷仍必须通过 AES-GCM 认证；程序不自动执行重建出来的 EXE。当前恢复组件限制为最多两个输入文件、128 个恢复文件、32768 个源切片、64 MiB 最大切片和 2 TiB 受保护数据；加密格式的大文件上限与此不同。

## 验证与仍需审阅的范围

测试工程包含公开密码学已知答案、独立格式解码、逐文件 SHA-256 对比，以及恶意/损坏输入与文件系统边界案例。运行：

```powershell
dotnet run --project tests/TwoPassword.Tests -c Release
```

测试报告输出到被 Git 忽略的 `artifacts/test-results.json`。报告中的实际运行环境和通过/失败/跳过状态才是该次执行的证据。

公开向量测试用于检查依赖/API 使用，不代表 NIST CAVP 认证。当前版本尚未经过独立第三方密码学与渗透测试审计。未来审阅应重点检查信封组合、归档解析边界、文件系统竞态、资源限制、更新/签名链和错误恢复。
